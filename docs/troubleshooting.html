แก้ปัญหา

ตรวจตามลำดับ: บอร์ด → WiFi → MQTT → gateway → หน้าเว็บ → AI ปัญหาส่วนใหญ่อยู่ต้นทาง เปิด Serial Monitor (pio device monitor) ก่อนเสมอ แล้วดูว่าบอร์ดพิมพ์อะไร

คำสั่งตรวจสุขภาพระบบ

docker ps                                   # ต้องเห็น mosquitto กับ mqtt_collector
curl localhost:5001/api/summary             # ต้องได้ JSON (latest ว่างได้ถ้ายังไม่มีข้อมูล)
docker logs gateway-mqtt_collector-1 --tail 30
docker logs gateway-mosquitto-1 --tail 30   # เห็นการเชื่อมต่อของบอร์ดไหม

บอร์ดและการอัปโหลด

อาการสาเหตุที่พบบ่อยวิธีแก้
อัปโหลดไม่ได้ / พอร์ตหาย / Device not configuredบอร์ดไม่อยู่ในโหมดโหลด หรือสายเป็นสายชาร์จกด BOOT ค้าง แล้วกด RESET หนึ่งครั้ง ปล่อย BOOT แล้วอัปโหลดใหม่ ใช้สายที่ส่งข้อมูลได้ ลองซ้ำอีกรอบ (บางครั้งสำเร็จรอบที่สอง)
Serial Monitor ไม่ขึ้นอะไรเลือกพอร์ตผิด หรือยังไม่รีเซ็ตบอร์ดหลังอัปโหลดกด RESET หนึ่งครั้ง ตั้ง baud 115200
ค่าเซนเซอร์เป็น 0 หรือ nanสาย I2C หลวมตรวจการเสียบเซนเซอร์ แล้ว RESET

WiFi และ MQTT

อาการสาเหตุที่พบบ่อยวิธีแก้
ต่อ WiFi ไม่ได้ชื่อ/รหัสผิด หรือเป็น 5 GHzตรวจ secrets.h และใช้ WiFi 2.4 GHz (ใช้ฮอตสปอตมือถือแทนได้)
ต่อ WiFi ได้แต่ MQTT ไม่ผ่านIP ใน Config.h ไม่ใช่ IP ของคอมพิวเตอร์ หรือไฟร์วอลล์บล็อก 1883หา IP ใหม่ (ipconfig getifaddr en0) แล้วอัปโหลดซ้ำ และอนุญาตพอร์ต 1883
WiFi โรงเรียนใช้ไม่ได้เครือข่ายกันไม่ให้เครื่องคุยกันเอง (client isolation)ใช้ฮอตสปอตมือถือ หรือรันตัวจำลองแทนบอร์ด

Docker และ gateway

อาการสาเหตุที่พบบ่อยวิธีแก้
docker ค้าง หรือ Cannot connect to the Docker daemonDocker Desktop ยังไม่พร้อม หรือดิสก์เต็มเปิด Docker Desktop รอจนพร้อม ถ้ายังไม่หาย รีสตาร์ทและเคลียร์พื้นที่ดิสก์
port is already allocated (5000/1883)มีโปรแกรมอื่นใช้พอร์ต (macOS ใช้ 5000)เรา map เป็น 5001 อยู่แล้ว ถ้า 1883 ชน ให้ปิด Mosquitto/stack เก่า: docker compose down ของโปรเจกต์เก่า
หน้าเว็บเปิดได้แต่ไม่มีค่ายังไม่มีข้อมูลเข้าดู docker logs gateway-mosquitto-1 ว่าบอร์ดต่อเข้ามาไหม หรือรัน simulator.py
ส่งข้อมูลแล้ว API ยังเป็นค่าเก่าเช็ก node หรือรูปแบบ JSONต้องเป็น {"node":1..4,"value":ตัวเลข} ค่านอกช่วง/ไม่ใช่ตัวเลขจะถูกทิ้ง ดูข้อความใน log

Telegram และ ngrok

อาการสาเหตุที่พบบ่อยวิธีแก้
Mini App เปิดเป็นหน้าเปล่าMINIAPP_URL ไม่ใช่ https หรือลิงก์ ngrok เปลี่ยนแล้วngrok ฟรีเปลี่ยนลิงก์ทุกครั้งที่เริ่มใหม่ แก้ .env แล้ว docker compose up -d mqtt_collector
ngrok ขึ้นหน้าเตือนก่อนเข้าหน้า interstitial ของ ngrok ฟรีหน้าเว็บของเราส่ง header ข้ามให้แล้ว เปิดผ่าน Telegram ปกติ
บอทไม่ตอบtoken ผิด หรือรันบอทสองที่พร้อมกันตรวจ TELEGRAM_BOT_TOKEN และปิด stack เก่า

AI และ Colab

อาการสาเหตุที่พบบ่อยวิธีแก้
แชตขึ้น “ตอบโดยกฎ” ตลอดยังไม่ได้ใส่ OLLAMA_URL ลิงก์หมดอายุ หรือ Colab หยุดแล้วดูว่าเซลล์สุดท้ายใน Colab ยังรันอยู่ ถ้าไม่ รันใหม่แล้วคัดลอกลิงก์ใหม่ใส่ .env
Colab: เซลล์ติดตั้งนานมากไม่ได้เลือก GPU หรือโหลดโมเดลครั้งแรกRuntime → Change runtime type → T4 GPU ครั้งแรกใช้เวลาหลายนาทีเป็นปกติ
Colab: Address already in useรันเซลล์ 2 ซ้ำRuntime → Restart session แล้วรันตั้งแต่ต้น
Colab: ReadTimeout ตอนทดสอบโมเดลยังโหลดไม่เสร็จ หรือใช้ CPUรอ 1 นาทีแล้วรันเซลล์ที่ 3 ใหม่ ตรวจว่าเป็น T4
ขึ้นว่าเกินจำนวนครั้ง (429)ถูกจำกัดการถาม 12 ครั้งต่อนาทีต่อคนรอสักครู่ (ตั้งใจจำกัดเพื่อกันถูกถล่ม)
AI เตือนความผิดปกติผิดๆข้อมูลอ้างอิงยังน้อย หรือสัญญาณรบกวนมากรอให้มีข้อมูลอย่างน้อย 20 ค่า หรือเพิ่ม z_limit
ยังไม่หาย บันทึก (1) อาการที่เห็น (2) ข้อความใน Serial Monitor / log (3) สิ่งที่ลองแก้แล้ว แล้วถามครูหรือถาม AI พร้อมแนบ 3 อย่างนี้ จะได้คำตอบตรงขึ้นมาก
