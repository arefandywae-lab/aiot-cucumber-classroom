ความปลอดภัย

ระบบที่ “ทำงานได้” ไม่เท่ากับ “ปลอดภัย” หน้านี้บอกว่าโปรเจกต์นี้ป้องกันอะไรไว้แล้ว และยังเปิดช่องอะไรไว้ตั้งใจ เพื่อให้ห้องเรียนต่อได้ง่าย

ที่ป้องกันไว้แล้ว

เรื่องทำอย่างไรอยู่ที่ไหน
ตรวจข้อมูลขาเข้ารับเฉพาะ node 1–4 ค่าเป็นตัวเลขและไม่เกิน 1e9 ข้อมูลแปลกถูกทิ้งmqtt_app.py
จำกัดการถาม AI12 ครั้ง/นาที/คน และ 60 ครั้ง/นาทีรวมrest_app.py
จำกัดเว็บที่เรียก APICORS อนุญาตเฉพาะเว็บคอร์สนี้CORS_ORIGINS
ความลับไม่ขึ้น GitHub.env, secrets.h อยู่ใน .gitignore.gitignore
ยืนยันผู้ใช้ Telegramตรวจลายเซ็น HMAC ของ initData ฝั่งเซิร์ฟเวอร์check_init_data()
AI ล่มก็ไม่พังถอยไปใช้กฎง่ายๆanswer_question()

ที่ยังเปิดไว้ (ตั้งใจ)

ช่องโหว่เสี่ยงอะไรถ้าจะแก้ ต้องเรียนเรื่อง
Mosquitto ไม่ต้องล็อกอินใครในเครือข่ายเดียวกันส่งค่าปลอมเข้าระบบได้username/password, TLS บน MQTT
ข้อมูลเป็น HTTP/MQTT ธรรมดาในห้องดักอ่านได้ในเครือข่ายเดียวกันTLS / HTTPS
ใครมีลิงก์ ngrok ก็อ่าน API ได้เห็นค่าอากาศของห้อง (ไม่มีข้อมูลส่วนตัว)การยืนยันตัวตน (authentication)
บอทคนแรกที่ /start เป็นเจ้าของคนแปลกหน้าชิงเป็นเจ้าของบอทตั้ง TELEGRAM_ALLOWED_CHAT_ID
ข้อความแชตไปที่ LLM บนอินเทอร์เน็ตข้อมูลส่วนตัวรั่ว และถูกหลอกให้ตอบผิด (prompt injection)ความเป็นส่วนตัว การจำกัดสิทธิ์ AI

คำถามชวนคิด

  1. ถ้าคุณอยู่ห้องเดียวกัน จะทำให้กราฟของเพื่อนขึ้นว่า “ผิดปกติ” ได้อย่างไร (ตอบด้วยข้อมูลในหน้านี้ ไม่ต้องลองกับระบบของผู้อื่น)
  2. ถ้าระบบนี้สั่งเปิด-ปิดไฟบ้านจริง ช่องโหว่ข้อไหนอันตรายที่สุด
  3. ทำไม AI ในโปรเจกต์นี้ “อ่านค่าและตอบ” เท่านั้น ไม่ได้ “สั่งงานอุปกรณ์”
ข้อตกลง ทดลองเฉพาะกับอุปกรณ์และเครือข่ายของตัวเองหรือที่ได้รับอนุญาตเท่านั้น
