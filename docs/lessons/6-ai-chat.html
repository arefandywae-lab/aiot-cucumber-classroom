บทที่ 6

AI แชทบน Colab

AI แบบที่สองคือ LLM (โมเดลภาษาขนาดใหญ่) ที่อ่านค่าเซนเซอร์ล่าสุดแล้วตอบคำถามเป็นภาษาไทย โมเดลใหญ่ต้องใช้การ์ดจอ เราจึงยืม GPU ฟรีของ Google Colab แล้วให้ gateway เรียกผ่านลิงก์

ลองเล่นก่อน: กฎ กับ LLM ต่างกันอย่างไร

ช่องนี้ใช้ ‘กฎ’ ตอบ (แบบเดียวกับที่ gateway ใช้ตอนไม่มี LLM) ส่วนด้านล่างคือข้อความที่จะส่งให้ LLM จริง ลองถามคำถามที่กฎไม่รู้ เช่น “พรุ่งนี้อากาศเป็นยังไง”

เปิดใช้ LLM บน Colab ในห้าขั้นตอน

เปิดโน้ตบุ๊ก LLM บน Colab

  1. เปิดโน้ตบุ๊กกดปุ่มด้านบน (ต้องล็อกอินบัญชี Google) ไม่ต้องดาวน์โหลดหรือติดตั้งอะไร
  2. เลือก GPUเมนู Runtime → Change runtime type → T4 GPU แล้วกด Save
  3. กด Run allเมนู Runtime → Run all เซลล์ติดตั้งใช้เวลา 3–6 นาทีครั้งแรก (เซลล์ที่ 3 จะตอบ "ตอนนี้ร้อนไหม" ให้ดูว่าโมเดลใช้ได้)
  4. คัดลอกลิงก์เลื่อนไปเซลล์สุดท้าย จะมีข้อความ ✅ พร้อมบรรทัด OLLAMA_URL=... คัดลอกสองบรรทัดนั้น แล้ว ปล่อยเซลล์ให้รันค้างไว้ อย่าปิดแท็บ
  5. บอก gatewayวางลงใน gateway/.env แล้วรีสตาร์ท
# gateway/.env
OLLAMA_URL=https://xxxx.trycloudflare.com
OLLAMA_MODEL=qwen2.5:3b
docker compose up -d mqtt_collector

เปิดหน้าเว็บแล้วถามในช่องแชท ใต้คำตอบจะบอกเสมอว่า ตอบโดย LLM หรือ ตอบโดยกฎ

ตรวจว่าเชื่อมสำเร็จ

  • เซลล์ที่ 3 ใน Colab พิมพ์คำตอบภาษาไทยออกมา
  • curl https://xxxx.trycloudflare.com/api/tags ตอบรายชื่อโมเดล (รันจากเครื่องคุณ)
  • หน้าเว็บ: ถามแล้วใต้คำตอบขึ้น “ตอบโดย LLM”
  • ถ้ายังขึ้น “ตอบโดยกฎ” ดูวิธีแก้ที่ แก้ปัญหา

ทดลอง: ทำให้ AI ดีขึ้น (หรือพังให้ดู)

ในโน้ตบุ๊กมีเซลล์ ลองเล่น ที่ปรับคำถาม ค่าเซนเซอร์ และ system prompt ได้โดยไม่ต้องแก้โค้ด

ทดลองสังเกตอะไร
ถาม “พรุ่งนี้ฝนตกไหม” ด้วย system prompt เดิมโมเดลยอมรับว่าข้อมูลไม่พอ หรือเดามั่ว
ลบประโยค “ห้ามเดาตัวเลข” ออกแล้วถามซ้ำคำตอบเริ่มมีตัวเลขที่ไม่มีในข้อมูลไหม
ติ๊ก “ตรวจพบความผิดปกติ” แล้วถาม “มีอะไรน่ากังวลไหม”โมเดลใช้ผลของ AI ตัวแรก (z-score) ได้ถูกต้องไหม
เปลี่ยนโมเดลเป็น qwen2.5:1.5bเร็วขึ้นแต่ตอบแย่ลงไหม
ถามภาษาอังกฤษ หรือถามเรื่องไม่เกี่ยวกับอากาศโมเดลอยู่ในกรอบที่ตั้งไว้ไหม
ไม่อยากใช้ Colab ติดตั้ง Ollama บนเครื่อง (RAM ตั้งแต่ 8 GB) รัน ollama pull qwen2.5:3b แล้วตั้ง OLLAMA_URL=http://host.docker.internal:11434 หรือเว้นว่างไว้ ระบบจะตอบด้วยกฎอัตโนมัติ ไม่พัง

มันตอบจากอะไร

gateway ไม่ได้ให้ LLM “เดา” แต่ส่งค่าเซนเซอร์ล่าสุดและผลตรวจผิดปกติไปในคำถามด้วย (ดูกล่อง prompt ในสนามเล่นด้านบน) พร้อมคำสั่งให้ตอบจากข้อมูลที่ให้เท่านั้น เทคนิคนี้เรียกว่า grounding ช่วยลดการเดามั่ว แต่ไม่ได้กำจัดหมด

ระวัง ลิงก์ Colab ใครได้ไปก็ใช้โมเดลของคุณได้ อย่าแชร์ต่อ ข้อความแชตผ่านเซิร์ฟเวอร์ของ Google/Cloudflare อย่าพิมพ์ข้อมูลส่วนตัว และ LLM ตอบผิดได้ อย่าใช้ตัดสินใจเรื่องความปลอดภัย

ทบทวน

ทำไมต้องส่งค่าเซนเซอร์ไปพร้อมคำถาม แทนที่จะถามโมเดลตรงๆ

โมเดลไม่รู้ค่าจริงของห้องเรา ถ้าไม่ส่งไปจะเดา การส่งข้อมูลจริงให้ (grounding) ทำให้คำตอบอิงข้อเท็จจริง

ทำไมต้องมีกฎสำรองเมื่อ LLM ใช้ไม่ได้

ระบบต้องไม่พังเมื่อส่วนใดส่วนหนึ่งล่ม Colab ฟรีหยุดเองได้ จึงออกแบบให้ล้มเหลวอย่างปลอดภัย

ถ้า LLM บอกว่า ‘ไม่มีความผิดปกติ’ แต่ z-score เตือน ควรเชื่ออะไร

ผลคำนวณจาก z-score ตรวจสอบย้อนได้ ส่วน LLM อาจตอบผิด จึงควรเชื่อตัวเลขที่คำนวณได้ก่อนแล้วไปดูว่าทำไม LLM ตอบต่าง
