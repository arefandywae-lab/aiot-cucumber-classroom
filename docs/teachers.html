เตรียมก่อนคาบ

  • รัน gateway หนึ่งเครื่องต่อกลุ่ม (หรือหนึ่งเครื่องทั้งห้อง) และเช็กว่า WiFi 2.4 GHz ใช้ได้
  • ถ้าห้องมี WiFi ที่บล็อกอุปกรณ์คุยกัน ให้ใช้ฮอตสปอตมือถือแทน
  • เตรียม devices/simulator.py และ devices/scenario.py ไว้ให้กลุ่มที่บอร์ดไม่พอ (ดู ไม่มีบอร์ด ใช้ตัวจำลอง)
  • บทที่ 5 และ 6 มีสนามเล่นในหน้าเว็บและโน้ตบุ๊ก Colab ให้ นักเรียนกดปุ่มเปิดเองได้ ไม่ต้องติดตั้ง
  • เปิด Colab ล่วงหน้า 10 นาที โมเดลโหลดครั้งแรกใช้เวลา

เกณฑ์ประเมินเสนอ

  • อธิบายได้ว่าข้อมูลเดินทางจากบอร์ดไปหน้าเว็บอย่างไร (วาดแผนภาพ)
  • อธิบายได้ว่า z-score บอกอะไร และตั้ง z_limit แล้วเกิดอะไรขึ้น
  • ยกตัวอย่างคำถามที่ LLM ควรปฏิเสธ/บอกว่าไม่รู้ พร้อมเหตุผล

ความปลอดภัยและข้อมูลส่วนบุคคล

  • Mosquitto ในโปรเจกต์เปิดแบบไม่ต้องล็อกอิน (allow_anonymous true) เพื่อให้บอร์ดต่อง่าย เหมาะกับห้องเรียนเท่านั้น อย่าเปิด port 1883 สู่อินเทอร์เน็ต ใครอยู่ WiFi เดียวกันสามารถส่งข้อมูลปลอมเข้ามาได้ gateway จึงรับเฉพาะ node 1–4 และค่าตัวเลขที่ถูกต้อง
  • API เปิดให้ใครมีลิงก์ก็อ่านได้ (ข้อมูลเป็นสภาพอากาศเท่านั้น) /api/ask จำกัด 12 ครั้ง/นาที ต่อ IP และรวมทั้งระบบไม่เกิน 60 ครั้ง/นาที (ป้องกันการใช้โมเดลถี่เกินไปแบบพื้นฐาน ไม่ใช่การยืนยันตัวตน และ IP จะน่าเชื่อถือเมื่อผ่าน ngrok เท่านั้น) และ CORS อนุญาตเฉพาะ GitHub Pages ของโปรเจกต์ ถ้าเปิดลิงก์ ngrok ให้คนอื่น ให้ปิด ngrok เมื่อเลิกใช้
  • เก็บ token/รหัส WiFi ใน .env และ secrets.h ซึ่งไม่ถูกอัปโหลดขึ้น GitHub
  • ข้อมูลที่เก็บเป็นค่าสภาพอากาศเท่านั้น ไม่มีข้อมูลระบุตัวบุคคล
