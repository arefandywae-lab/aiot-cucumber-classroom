ทำงานกับ AI อย่างไร (flow สั่งงานและตรวจงาน)

โปรเจกต์นี้พัฒนาโดยมี AI (Claude Code) เป็นผู้ช่วยเขียนโค้ดและเอกสาร ส่วนนี้สรุป วิธีสั่งและวิธีตรวจ เพราะการเชื่อผลของ AI โดยไม่ตรวจเป็นความเสี่ยงที่ใหญ่ที่สุด

1 กำหนดโจทย์เป้าหมาย กลุ่มเป้าหมาย ข้อจำกัด
→
2 ให้ AI สำรวจอ่านโค้ด/ตัวอย่างที่มี ก่อนเขียน
→
3 ให้ AI ลงมือทีละชิ้นเล็กๆ
→
4 ตรวจเทสต์ + ของจริง
→
5 แก้/ถามต่อวนกลับ

ตัวอย่างการสั่งงานจริงในโปรเจกต์นี้

ขั้นสิ่งที่สั่งสิ่งที่ตรวจ
กำหนดโจทย์ส่งข้อกำหนดงาน + เลือก: กลุ่มเป้าหมาย ม.ปลาย, AI ทั้งตรวจผิดปกติและแชท, ใช้ Colab, UI ทั้งเว็บและ Telegramเลือกเองทุกข้อ ไม่ปล่อยให้ AI เดา
สำรวจ"ดูไฟล์ใน demo_05_iot ว่ามีอะไรให้ใช้ซ้ำ"เช็กว่ามี token/รหัสผ่านติดไฟล์ไหมก่อนขึ้น GitHub
เขียนโค้ด AIสร้าง ai_helpers.py (z-score + แชท + fallback)เขียน unit test 6 ข้อ รันผ่าน (pytest tests)
ทดสอบจริงแฟลชบอร์ด รัน Docker เปิด Telegramดู Serial Monitor, log ของ broker, หน้าจอ Telegram จริง
ส่วนที่ทำไม่ได้Colab notebookAI ไม่มีบัญชี Colab ให้ทดสอบ จึงบอกตรงๆ ว่ายังไม่ได้รันจริง ให้ครูลองก่อนใช้

กฎที่ใช้ตรวจงาน AI

  1. ให้ AI บอกว่าทดสอบอะไรไปแล้ว/ยังไม่ได้ทดสอบอะไร และไม่เชื่อคำว่า "น่าจะใช้ได้"
  2. ของที่มีผลภายนอกต้องถามก่อน เช่น เขียนทับโปรแกรมในบอร์ด (AI ถามก่อนแฟลช) หรืออัปโหลดขึ้นอินเทอร์เน็ต
  3. ความลับไม่ผ่านแชท/ไม่ขึ้น GitHub ใช้ .env และ .gitignore
  4. ให้ AI อธิบายโค้ดที่เขียน ถ้าอธิบายให้เพื่อนฟังไม่ได้ แปลว่ายังไม่เข้าใจพอจะส่งงาน
  5. เปิดดูของจริง ตัวเลขจากบอร์ด หน้าจอจริง ไม่ใช่แค่ดูข้อความที่ AI รายงาน

โครงสร้างโปรเจกต์

devices/      โปรแกรมบอร์ด Cucumber + ตัวจำลองข้อมูล
gateway/      Docker: Mosquitto + REST API + หน้าเว็บ/Telegram
ai/colab/     โน้ตบุ๊กรัน LLM บน Colab
docs/         เว็บคอร์สนี้ (GitHub Pages) สร้างจาก tools/build_site.py
tests/        unit test ของส่วน AI
